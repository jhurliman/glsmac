# Ordered live citizens and riot consequences

This implementation connects the frozen citizen kernels to actual Base worker,
energy, population, production and owner-turn callers. Read-only Psych/resource
queries report the current result without changing the saved status or random
streams. Upkeep retains the actual second resource/citizen pass before the
status decision. Food consumes incoming Golden Age status; mineral posting
consumes incoming riots. A facility destroyed afterward changes maintenance,
not the already calculated income/research categories.

The ordinary ongoing-riot branch performs the mandatory POLICE CRT draw before
protection, then the measured ordered facility search. Exhausted negative-POLICE
searches select a recipient from retained former-owner/activity/relationship
authority. The positive-human transfer is prepared before any publication:
Base policy/facility/production cleanup, inner-radius Unit conversions, remote
homed-Unit losses, full-word masks, per-design counts, retained Base totals,
activity and battle targets, territory/visibility, and the third recipient
resource/citizen/support pass. A transfer returns before former-owner research,
ecology, income or maintenance. The original owner continues its live record
scan. A later recipient visits the transferred Base normally; an earlier owner
does not revisit this year. See the [native traversal receipt](riot-defection-owner-traversal.md).

The authenticated worker transaction has a distinct riot-transfer admission;
it does not weaken military capture's existing first-capture boundary. Stable
Base/Unit identities survive conversion. The frontend rebuilds an already
published Unit view with DESPAWN then SPAWN for its new faction. Accounting-only
changes preserve existing pending publication and selection identity.

Support/pacifism marker publication uses the final actual roster and ordered
support result, including surviving newborns. It changes only matching current
owner/home records and preserves unrelated full-word bits and legacy full-word
absence. Partial Hurry's paid marker survives riot cleanup and is cleared by
the later processed current-owner reset, not by ownership change itself.

## Development-save recovery

Older development frames may lack a Base's former faction. If an actual riot
needs that history, the current Base attempt remains unpublished and asks the
player explicitly. Cancel retains the checkpoint/question. The accepted repair
has saved migration provenance; no current-owner or zero fallback is inferred.
The continuation distinguishes a whole Base attempt, an already accepted
Colony Delay/Screen prefix, and an abandonment successor's existing cached tail.
It never replays earlier production or another Base. A stale request cannot
repair a different question. A deferred Screen following transfer is read-only;
closing it resumes the already normalized old-owner cursor.

Base context V5 retains optional full status and fresh former-owner history;
conventional Unit V6 retains optional full state and accounting markers (legacy
Unit4/native5 dispatch remains strict). Simulation V30 adds optional per-slot
battle targets after the unchanged native-factory V29 suffix. Legacy absence is
preserved. The inner custom-design codec writes legacy V1 byte-for-byte unless
known optional name or measured riot-result metadata requires V2. It preserves
the actual source definition identity and known flags/prerequisite/auxiliary
bytes; unknown source names stay unknown.

there is no original Psych screenshot-diff claim.


## Inactive former recipients and load repair

The [frozen inactive-recipient contract](riot-inactive-former-recipient.md) closes
an earlier admission hole. A positive bound former faction receives the Base and
eligible Units while remaining inactive. No initializer, restart, activation,
human-control change or extra draw is substituted. Existing economy, technology,
custom-design namespace, pending debit, diplomacy and loss history stay owned by
that faction; only the measured transfer deltas are published.

Persistent Base/Unit identity is distinct from permission to act. A synchronous,
exact-recipient private calculation scope admits its retained providers during
preparation, restores on failure, and expires before publication callbacks. The
recipient's citizen prefix/bureaucracy consume its actual saved human bit. Public
production/work commands retain active-owner guards; movement checks activity
explicitly. An inactive Base screen uses its tagged retained resource calculation,
withholds fresh energy/growth forecasts and remains read-only.

Canonical traversal retains all bound owner memberships so ownership normalization
and suspended snapshots represent inactive-owned entities. Inactive owner rows
skip the entire Base pass and owner summary/debit/ecology tail. Active recipients
retain ordinary earlier/later traversal; inactive recipients get no extra food or
old/new-owner posting from the ownership-change return.

After actual snapshot entities and home links are registered, load repair sets
activity from owned Bases or original design role8 (Colony Pod), clears it otherwise,
and preserves human control, retained fields and RNG. Saved continuation membership
is decoded before this repair; resumption consults the repaired activity. Ordinary
Units alone do not activate an owner. A retained port human-defeat request that
would contradict the repaired roster is rejected before any activity writes; this
is an explicit port admission boundary, not evidence of original ending behavior.

Validation: eight actual transfer compositions include inactive human/AI recipients,
transferred Colony Screen, and old-peer research suspension/save/Start/answer.
Seven actual Start controls cover Base/Pod/ordinary-Unit/empty-roster repair,
human-bit/retained-state/RNG canaries and contradictory-ending rejection. Current
support remains the admitted default/retained Rover design domain; arbitrary
inactive custom designs and full AI play are separate unfinished milestones.
