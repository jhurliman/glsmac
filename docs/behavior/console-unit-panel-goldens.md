## Important limits on what the real backdrop distinguishes

**The native shadow pass changes zero backdrop pixels in all twelve cases.**
It still executes and writes its completed mask before the body. But style18's
center uses only palette indices65 and196, and this installation's loaded
shadow table maps65→65 and196→196. Consequently:

* The native shadow-only crop equals the original framed-panel crop.
* The native shadow-plus-body crop equals a separate original body-only copy
  over that same panel.
* Shadow/body pixel overlap is recorded, but final colors cannot prove copy
  order on this particular background. The earlier
  [patterned native targets](live-ground-shadows.md) remain the discriminator
  for blend lookup, shadow-first/body-second ordering and shadow suppression.

**Horizontal roster phase also has a degenerate visual result in this asset.**
The source contract is still console-local modulo24, and later cells preserve
their absolute origins. However, the actual24×24 center tile is constant in x
and repeats every2 rows in y. Roster1 and roster2 therefore have identical
local background and final Unit crop hashes for a given design. Roster0 differs
because its crop includes the shared panel's left border. Do not invent distinct
hashes merely because the modulo24 x-phase numbers differ.

Adding the screen y-origin511 before sampling would shift vertical phase by an
odd number and remains wrong. See the source-backed
[frame/phase recipe](console-panel-backdrop.md). These goldens establish the
real image while that recipe establishes phases the simple artwork cannot
visually distinguish.

## Native stages and pixel encoding

Each case records four native crop stages:

| Fixture key | Actual capture |
| --- | --- |
|`panel_before`|Target at entry to original shadow copy`5f1ce0`|
|`shadow_only`|Target at entry to original body copy`5f12c0`, after the shadow copy returned|
|`shadow_body`|Target after complete`4d7860` helper returns normally|
|`body_only`|Additional original`5f12c0` copy of the captured body over a reset native panel; no extra3D draw|

Indexed crops are top-down rows with no padding. RGBA crops are top-down,
row-major **R,G,B,A bytes**, using the active native palette RGB and alpha255
for every pixel. These are opaque panel crops; index9 must not become alpha0
here. RGBA is a declared host conversion of original indexed output, not a
claim that the original renderer produced RGBA.
