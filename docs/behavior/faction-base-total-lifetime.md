# Faction Base total: authority and lifetime

RE-SMAC-FACTION-BASE-TOTAL-001, 2026-10-18. Pinned stock SMAC.
[Literal controls and reused observations](faction-base-total-lifetime-cases.json).

**Regional Q's N and leading-human dominance use the same retained signed
32-bit faction Base total.** It is maintained by immediate action deltas and
an owner-summary recount. It normally equals current owned Base records after
those operations on coherent state, but it is not an on-demand entity count.
Neither consumer derives it by summing regional bytes.

## Owner summary refresh and consumer order

The complete owner-summary producer first clears **only the requested owner's**
total. Its global Base-record walk increments that total once for every record
whose current owner matches. For each matching Base it separately updates the
population aggregate, then later its tile's regional Base byte. All Base records
are traversed before the Unit phase and subsequent regional strategy decisions.

The Q calculation therefore reads the completed new N for that owner. Four
complete summaries replace total777 with0,1,5 or256 from controlled current
records. A peer's888 remains888, even in the mixed-owner case. At every observed
Q read, the value is the requested owner's completed total. These are controlled
record arrays, not organically founded256-Base campaigns.

The256-record discriminator produces **N=256 while the regional byte sum is0**
because all256 contribute to the same byte. N is not reconstructed from those
bytes, and does not wrap with them. The mixed case counts5 matching records
and ignores one foreign record, independently of the peer's stale total.

Dominance reads this same field for its **queried retained score leader**.
That can be a different faction from the owner whose summary is running.
The current summary does not refresh every peer's total. The existing native
pressure controls demonstrate six live leader-owned records with retained N5
failing admission, versus retained N6 passing under otherwise matching inputs.
The predicate preserves faction state; it does not repair the mismatch.

## Fresh initialization, restart and last Base

prefixes preserve it. Four poisoned controls cover owners1/2. However, **the
no-Base disposition caller explicitly writes N=0 before calling the nonzero
initializer**. It first checks actual global Base records: any remaining owned
record returns without that reset or restart.

Two new native disposition prefixes distinguish this: no live owned Base plus
stale N777 reaches the restart-child entry with N0; one live owned Base plus

mistaken for preservation through the entire disposition/restart path.

These complete outcomes are reused; no new broad restart/search audit is added.
