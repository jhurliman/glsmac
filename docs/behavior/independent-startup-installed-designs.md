# Installed predefined designs and early localized names

The independent startup catalog now comes from the installed alpha.txt unit/component/technology rows and the relevant labels.txt entry, with source hashes. `startup_predefined_design_reference.py` owns the complete 59dfc0 pool transformation for the stock fourteen rows. Component cost reuses the earlier checked pure cost arithmetic; capacity and automatic roles are reconstructed from source. Native output records are expectations only.

Two complete native loader runs compare all 26,624 bytes of the 512-design pool, all eight faction records and 468 ordered numeric stores. One starts from zero storage; the other poisons the full pool. This verifies preserved bytes, including unused records, name tails, byte 47 and unrelated fields. The original installed section/token readers and all gameplay builder/cost/capacity/role helpers run without substitution.

The loader writes the name and prerequisite before constructing components at Fission reactor 1. It computes cost, capacity and roles, then applies row overrides: nonnegative plan replaces the automatic plan; nonzero cost/capacity replace calculated values; icon is always assigned modulo 256. Overriding plan does not replace the second automatic role byte at offset 43. Builtins receive active flags 1, exclusion byte 0, owner mask 255; byte 47 remains untouched. No prototype-complete bit is implied by this initialization.

`startup_localized_early_names_reference.py` closes the real 594320 paths for fresh Hand Weapons/Fission Synthmetal infantry defenders and Speeder reconnaissance designs without abilities or name collisions. Synthmetal uses the defense short name plus one of the infantry defense labels. Selection parity starts with `(reactor - 1) XOR owner`, low bit, then XORs the armor strength low bit. With stock Synthmetal strength 2, odd owners get `Synthmetal Garrison`, even owners get `Synthmetal Sentinels`. Speeder reconnaissance gets the localized Scout label at labels-table offset 0x248 plus the chassis Rover label. These strings come from assets, never native result-label inputs.

Eighteen complete native constructor controls compare full pool/faction records and 357 ordered numeric stores with original automatic naming. A further 56 complete 597de0 controller runs cover every owner, four difficulties, the faction's stock named starting technology and a combined early-technology control. They start from the actual installed fourteen-design catalog, run original naming, and compare all pool/faction bytes, 3,844 numeric stores, constructor requests, first-new-design state and 64 caller marking/selection stores. This supersedes the earlier supplied-name/basic-three admission for this early profile.

The general naming routine is much broader: arbitrary advanced weapons/reactors/abilities, existing names and collision suffixes are not covered by this label model. The controller remains restricted to the earlier named-starting-technology, fresh-own-block, no Bases/Units/contacts/projects profile. Full later-faction resource contexts and the seven-faction startup controller remain separate gates.

`check_generated_startup_installed_first_base.py` additionally composes the independent installed pool and real automatic names with the owned generated first Base. Its Base production costs are read from independently initialized design records. The original catalog journal verifies the entire pool at startup entry, after Gaia's early-design caller, and at the first Base's completed resource boundary.
