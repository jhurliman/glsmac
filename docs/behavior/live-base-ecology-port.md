# Live Base ecology calculation

The ordinary and upkeep resource passes now calculate eco-damage using the
measured rules in `SmacEcology.cpp`. The fresh GSE resource result exposes
`eco_damage`; an unavailable authority produces `null`, never an invented zero.

The consumer reads every valid square of the 21-square radius, including
unworked and unowned improvements. Worked status comes from the explicit
allocation bits, including the independently retained center bit. It uses the
actual gross processed minerals before support, candidate population, mining
satellites, authenticated installed/staged local facility roles, current PLANET,
retained technology score and Future Tech counter, owner/global difficulty,
saved clean-mineral/atrocity history, frozen Sea Level Rises rule, mutable world
native life/sea offset and retained perihelion phase. The admitted no-project
campaign establishes absence of Singularity Inductor, Pholus Mutagen and Voice
of Planet; this is not inferred from missing project fields.

No resource query changes history, posts an aggregate, consumes a CRT/gameplay
random draw or triggers an ecology event. The separate owner-tail event consumer
is described below. Opening production for ecological
facilities also requires their event-driven clean-mineral history writer;
this change does not admit those completion targets.

The last committed upkeep pass preserves its damage in inner cache V2. V1
migrates with unavailable damage. Colony continuation V3 carries the same
field; V1/V2 retain absence. Resuming a new known-damage question checks that
the live damage still agrees. A legacy unknown value is not reconstructed
and substituted into its historical first pass. Founding's separately retained
allocator pass remains unavailable until it has an actual ecology calculation.

Focused validation uses the cached native build. The live fixture checks:

- 21 Boreholes, two selected bits: raw terrain points191, scaled23;
  center mineral1 plus capped worker2, clean allowance16, burden10;
  technology100, PLANET0, native life1 and Citizen factor2 give damage20.
- A road on an unworked radius square raises damage to22. Clearing the center
  selection bit reduces it to20 without changing automatic center intake.
- Active perihelion doubles damage to40; retained clean history20 reduces it
  to0 without installing facilities.
- Repeated native/GSE queries preserve the snapshot and both RNG states.
- Actual upkeep retains damage20 and world restore preserves it; removing
  current world authority makes a fresh query unavailable while preserving
  the historical cache.
- Independent typed V1/V2 cache fixtures preserve absence and signed32 damage,
  including137 and both signed boundaries, and reject narrowing/truncation.

The selected native run passes12 groups, including actual Colony saved
questions, deferred Screen/research/Start, campaign restore and perihelion
boundaries. Correctness analysis passes the six changed production translation
units. Seven focused groups also pass with ASan/UBSan instrumentation on the
live calculation, resource processing, cache, production and canonical snapshot
translation units; other objects reuse the current normal build and leak
detection is disabled. This is calculation/cache integration, not a claim that blooms, aggregate
posting, ecological facility completion or every ecological event is playable.


## Live post-research event transaction

Ordinary campaigns now connect the retained final resource pass to the actual
handler after research: aggregate contribution, mandatory existing CRT draw
(including damage0), saved rule gates, ordered selection and terrain plan.
The AI post-terrain gate consumes its actual extra CRT calls and undoes only H;
terrain and earlier draws remain. One-shot, H and Voice holds follow in order.

The owning Map transaction validates live preimages, prepares native authority,
site-cache invalidation and renderer payloads, and exposes a temporary staged
view to the existing ordered native factory. Failed preparation publishes
nothing. Class-only updates preserve contours and shared corner heights. The
single admitted focused viewer receives the full direct-cell item memory copy;
peer memory/exploration is preserved until actual native sight discloses it.
Ordinary notices use their separate viewer admission.

Frozen ecology profile V3 retains the native warming-frequency pair. Simulation
V40 adds the independent signed pending/increment/divisor/accumulator schedule,
with fresh zero authority and absent history on V39 and older migration. The
threshold scheduler increments the admitted global count, applies the verified
clamps/severity, updates native climate-extra and reschedules the complete signed
pending amount. It consumes no guessed RNG budget.

The complete deferred climate recalculation and admitted volcanic eruption
remain untranslated. Their actual admission is evaluated; an admitted eruption
or due sea step explicitly stops before publication rather than suppressing the
branch or fabricating terrain effects. The later-step accumulator advances
normally before a step is due. Loaded native factories requiring the separate
assignment tail retain their existing explicit rejection. These limits are
material beyond the early campaign slice; this is not complete climate parity.
Legacy diagnostic worlds lacking frozen event rules retain aggregate-only
capability without invented rule words or frequency defaults.


## Full-plane climate preparation

The owning Map adapter now projects the actual live material, occupancy and
remembered improvements into the existing climate plane. Its prepared climate
transaction invokes the original-checked region rebuild and coastal postpass,
retaining area history, Freshwater and raw coastal words. It stages the complete
resource policy, topology/site invalidation, shared display corners, physical
terrain and positive-faction remembered item changes. Cross-category remembered
writes do not add exploration. Queries restore all terrain, geometry caches and
authorities on normal/exceptional exit; publication checks complete tile and
policy/knowledge/topology preimages.

The final territory consumer must complete the prepared transaction explicitly.
This adapter alone does not supply Base/Unit destruction. The existing live
climate/volcano caller guards remain until the owning entity transaction joins it;
this preparation is not permission to publish only terrain. The focused live Map test uses claimed startup and the actual owned save
codec to check detached preparation, injected-consumer rollback, stale-preimage
rejection, surface/contour/region publication and all-seven-memory preservation.

The admitted native-source campaign renders through an owned terrain snapshot,
not its hidden legacy mesh. A climate payload explicitly invalidates the complete
native Session/geometry/projector view and requests a fresh snapshot, preserving
viewer knowledge. The native renderer rebuilds the landscape and actor projector
heights from that snapshot. No borrowed mesh/texture lifetime changes threads.
After climate, hidden legacy atlas recipes are retired; later ordinary work still
publishes tile metadata and native snapshot invalidation, avoiding replay against
obsolete coastal recipes. Full legacy-mesh renderer support is not implied.

For aggregate entity coupling, Map preparation accepts an explicitly copied
candidate knowledge frame after the entity query has restored original live
registries. This preserves survivor observations and acquired exploration while
applying the evolving climate item-memory and occupancy words. The final Map
plan exposes separate Validate and noexcept Commit phases: the owner validates
all participating entity/map/notification plans before the first publication,
then commits without allocation or a second stale check after another participant
has already committed. Queries remain detached and can run before sealing.
