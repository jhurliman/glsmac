# Native CVR map placement

The original populated viewport copies the model renderer's complete 256-square color bitmap at 1:1 in the measured zoom0 scene-flag1 path. For the visible Scout, dispatcher anchor624,288 produces final copy origin546,210: the returned target anchor adds50 on each axis and the copy subtracts128. See [the frozen original viewport evidence](viewport-populated.md). Another original scene branch passes scale arguments [1,2], halving the image; that branch and arbitrary display profiles are outside this zoom0 control.

The port previously retained the correct model pixels but mapped the256-square texture onto the explicitly stored1x1 world rectangle. In the native96x48 projection that reduces the image to96x48 screen pixels. Native standard CVR map sprites now use256/96 by256/48 world extents and the renderer's cached returned target anchor. The model bitmap and target metadata share one immutable cache entry. Separate actors share the same pixel owner across native/legacy placement.

Actual UnitManager definition publication selects native geometry only for the standard1x1, centered128, zoom0/default-or-unit-scale descriptors in a native-projection world. Explicit custom dimensions/centers and other view scales retain their declared placement. Console cards keep their independent view and geometry. No model pixels, wire descriptors, game state or save format changes.

Cached build and the three real Scout/initialized-Scout/Rover definition, unit, preview and retained-texture groups pass. Their actual camera/actor/mesh tests verify the256-square final copy at dispatcher minus78 on both axes at heights0/25/6/3, independent legacy actors with shared pixels, and unchanged console-card dimensions. Targeted correctness analysis covers four changed production translation units plus the Unit consumer. These geometry controls do not establish the whole populated original frame, original glyph pixels, arbitrary zoom, moving models, or the alternative copy branch.

Focused ASan/UBSan instrumentation of the five affected frontend units and the backend test translation unit also passes all three groups using the owned GOG assets. Other linked objects use the normal cached build; leak detection was disabled, so this is a focused lifetime/bounds check rather than a whole-engine sanitizer claim.
