## Engine integration and limits

Retain the ordering: canonical initial bookkeeping and destination/profile/ZOC admission; optional encounter query and CRT draw; canonical native constructor; on success publish birth/sight/history and return without movement; on allocation failure continue; then allowance, canonical edge cost, selected-stream lottery, spending, unlink/placement and sight. A refused lottery returns one after endturn/failure writes; a successful birth returns zero with durable mutation. Neither Boolean is an all-or-nothing transaction result.

The pure model emits typed actions for the canonical constructor, history marking, endturn, failure state and relocation/sight. It does not reimplement the owning cost, combat, cargo or general sight engines. Its numeric inputs include dimensions, pattern/rules context, all Base coordinates, destination protection cells, history, stream selector, seeds, capacity and actual Scout state. Native trace assertions bind nearest selection/distance, threshold, source ZOC short circuit, cost, capacity failure branch and normal returns.

Existing headless redraw/presentation boundaries remain serialized. These are direct primitive calls, not completed human turns. General source-occupied diplomacy, concealed ZOC, sea/air/Psi, transport, special projects and nonnegative native assignment references remain separate branches.
