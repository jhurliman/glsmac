# Retained faction Base totals

The [original lifetime receipt](faction-base-total-lifetime.md) establishes that
regional strategy's N and leading-human dominance read one retained signed total
per faction. Current live ownership and the regional byte sum are separate
authorities. The copied source JSON SHA256 is
`768a02a8dde7ae1470b537ff7bcfba89963d1555631292eb2a36f964ff4e1688`.

Simulation V23 owns all eight signed words in `retained_base_totals`. New worlds
start with zero totals, including slot0 and unused positive slots. V11–V22 saves
retain explicit absence; neither loading nor one owner summary invents the
unavailable history of every other faction. Signed diagnostic words restore
exactly. Immediate deltas use checked wide arithmetic; original overflow beyond
ordinary signed32 counts is unmeasured.

All three existing creation routes—starting Base, running Pod founding and
generic canonical registration—stage one gaining-owner increment before
registration and publish it before the Base-spawn callback. Nonlast removal,
Colony abandonment and starvation stage one losing-owner decrement. Capture
stages old−1/new+1 independently of its deliberately stale regional bytes; its
temporary resource-query view includes these totals and restores them on every
query exit. A no-Base disposition explicitly clears the victim total to zero,
including the last-Base capture preview and final commit. The empty-faction
settlement path likewise clears its own total. Nonzero initializer preparation
does not itself recount or clear the field.

The ordinary post-Base owner summary counts current matching Base records and
publishes only that owner's new signed total with its other staged summaries.
It does not rerank factions. Founding/removal preserve deliberately stale count
offsets between those real recounts. Ordinary saved-world Start preserves the
saved total even when it disagrees with current Base records.
