# Stack marker bitmap, glyph and blink clarification

Supplement to the immutable native zoom/stack handoff47b8e09e. Same pinned original terran.exe SHA2560a61eb3642df750c0d5e516c3e3efeb4ad5ae7e1ce3163617759449327952a01. No foreground interaction or production edits.

**The extra stack marker is the raw flag silhouette in a single indexed color, with no order/status glyph.** It is not a duplicate fully composed badge. The raw sprite bank and active/exhausted variant match the primary flag. Native57037c calls5fcc90(bitmap,key=0,markerX,markerY,color=6aeed4[representativeOwner]);5703df calls5fd9e0(bitmap,key=0,primaryX,primaryY) on the same sprite object.

In the tested software bitmap path,5fcc90 compares each source index against the transparent key, skips matches, and writes the supplied low8 color index for all other source pixels.5fd9e0 skips the same key but copies the original non-key indices. The marker's extra argument is a **destination palette index**, not a palette pointer, alpha value or blend factor. Both make opaque indexed writes only at admitted source-mask pixels. Background behind key pixels survives. The six bitmap controls cover key0 and9, two fill colors, a sprite with its own(-1,-2) offset, and destination clipping. Even source index9 gets filled/copied when the actual key is0. Software scale1 is directly executed; hardware/DIB fallback and final scaled sprite coverage are not newly closed here.

The source sprite's own offset is added identically by both helpers. At the measured z0 anchor(100,76), chassis offset<=50, the marker call anchor is(100,76) and primary flag anchor(106,76), so the marker is six pixels left at the same y. At z8 the separation is nine. General separation is trunc(6*(z+16)/16), or trunc(6*globalScaleNumerator/globalScaleDenominator) for a positive scale override. If the chassis-offset field is>50, the marker is shifted left by that separation first and the primary restores the original anchor; otherwise the marker uses the original anchor and the primary shifts right. These are call anchors; add the shared sprite-internal offsets to obtain destination bounds.

The health rectangle and order/status text come **after** these two sprite calls. The order is loaded from representative Unit+17 at5706f8; text is drawn once through5f5f30 at570a54. It is never added to the marker bitmap. At z0 the observed primary(106,76) has glyph rectangle[116,81,127,95], i.e.[primaryX+10,primaryY+5,primaryX+21,primaryY+19]. Three visible-stack controls (normal, order2, selected-on) each emit exactly one marker, one primary, one health bar (two rectangle draws), and one glyph draw, in that order. Glyph lookup is supplied a fixedX and font calls are sinks: these controls establish ordering/admission/rectangle, not the original glyph string or rasterized font.

**Selection blink is shared.** The selected-off far-mouse path passes flags403;57020b..21a skips the entire marker/primary/health/glyph block. The body/model path precedes this gate. Near-mouse or whole-unit blink suppression omits the renderer entirely. A selected-on stack emits the same single marker/primary/health/glyph sequence as the ordinary stack. The marker does not blink independently, and a hidden primary must not leave an extra stack silhouette behind.

Port recipe: take the admitted representative raw flag sprite and its transparent mask; draw one solid faction-index silhouette at the marker anchor when count>1; draw the original-color raw flag at the primary anchor; attach health/order/status only once to the primary. Apply the same overlay visibility/blink decision to all of these. Do not copy a texture that already contains a glyph or health bar to create the marker.
