# RE-SMAC-STARTUP-ECONOMY-001: fresh-campaign economic defaults

Publication scope: this repository includes this handoff and its literal cases. Other research notes named as unpublished follow-ups below are outside this published evidence boundary and do not expand its claimed scope.

Seven installed faction profiles pass the original faction-initialization
prefix and a separate admitted fresh-game allocation-writer prefix. Poisoned
treasury, pending-debit, diplomacy, commerce and slider controls distinguish
actual writes from zero-filled fixture memory. See the
[seven profiles and fourteen maintenance calls](startup-economic-state-cases.json).
These bounded producers do not execute complete new-game placement or compose
initialization with the first treasury/research posting.

No initial treaty or pact is present in those relation flags. The existing
commerce producer (unpublished follow-up `commerce-pairing-and-income.md`) requires a treaty relation
and a partner base before pairing income, so these initial relations do not
produce treaty commerce. This is not a claim that every possible diplomatic
field or scenario starts empty.

The starting-energy value comes from the retained complete original rules-loader
capture. Faction ENERGY bonuses come from actual installed faction parsing.
The flat labs adjustment is a distinct definition value, separate from current
social RESEARCH and from labs allocation. Its original constructor explicitly
resets a poisoned value to zero in seven additional checks. Do not give the
University a flat lab bonus merely because it has positive social RESEARCH;
its actual startup free Network Node has separate effects.

Initialization and slider assignment occur at different points: the early
prefix establishes treasury/debit/relations but leaves the poisoned sliders
untouched. The later fresh-game writer sets psych0/labs5. Initializing only
the early prefix is insufficient to reproduce the final allocation.

## Free-facility maintenance

The ordinary maintenance body checks the faction's free-facility list for each
installed facility before charging its resolved maintenance. In the standard
profiles, Hive Perimeter Defense and University Network Node waive maintenance.
Fourteen complete calls install each of those facilities for each faction with
a deliberately supplied fee of 2: Hive pays 0 for Perimeter Defense, University
pays 0 for Network Node, and all other profile/facility combinations pay 2.
These synthetic positive fees distinguish waiver from an installed rule fee
that happens to be zero; they are not the installed maintenance prices.

The check requires the facility to be present and uses faction ownership of
the free-facility benefit. It is not a blanket waiver for every early facility
or a rule that all instances of Network Node are free. Later project discounts,
special Command Center pricing and facility loss on treasury deficits are
separate branches, not newly exercised here.

For posting, use [research submission scaling](research-submission-scaling.md)
and the returned two-base caller (unpublished follow-up `two-base-upkeep-posting.md`). The latter's
supplied slider labels have been corrected: that earlier experiment used
psych50%/labs0%, with residual labs from rounding. Its observed posting values
remain valid, but its controls are not fresh-campaign defaults.

## Boundaries

All seven profiles run in human slot one at ordinary difficulty3 with no scenario
or network game. The initialization prefix runs from the actual routine entry
and stops before placement; allocation executes the original admitted turn-zero
writer and stops before later placement/package logic. UI text storage is
supplied. Maintenance is a complete normal original return. No successful
placement, diplomacy result or maintenance debit is substituted. Saved/scenario
games, network starting reserves and respawn initialization remain separate.

The [returned last-base restart extension](last-base-restart.md) now checks
ordinary restart/refusal outcomes, replacement units and treasury/research state,
plus an actual replacement-Pod founding and following complete faction upkeep.
It retains explicit limits on generated placement, restart history and ending UI.

The fresh research-input producer receipt (unpublished follow-up `research-start-inputs.md`) now checks
initial S/A/D, pending Secrets, labs/fraction, target/cache and TECHCOST100,
plus the original discovery-rate row/token/clamp behavior. Later award/choice
and deferred settlement retain their separate execution boundaries.
