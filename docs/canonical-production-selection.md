# Canonical Base production selection

The existing Base-screen production panel now offers the supported, currently
eligible Scout, Former, Colony Pod and owned selected Spartan Rover. These are
actual frozen design identities, resolved through the configured presentation
roles; the selector does not infer designs from names. The local human owner
can choose a target and manufacture it through the existing canonical upkeep.
Other owners and legacy Bases show an unavailable selector. Facility/project
selection, workshop designs and queue editing remain outside this UI slice.

The read-only Base query copies the complete saved production state and reports
actual cost and the manual-switch result. The existing switch kernel consumes
frozen retool rules, original difficulty and installed positional facilities
(Skunkworks source 10). OK first displays a required retool confirmation; Cancel
does not post a command. A native cancellation also preserves the original
state. No target, mineral balance, baseline or queue is supplied as replacement
authority by the UI.

The native local event authenticates the current canonical Base and owner and
rechecks eligibility and presentation. A stale saved-state comparison or changed
post-switch balance is ignored, including duplicate queued confirmations. This
also prevents confirming a different loss after a facility change. No saved
schema or quote store is added. Successful selection stages both refresh queues
before swapping the existing production record; baselines and pending queue are
preserved by the switching kernel. Selection does not consume RNG.

Three focused native groups reuse the real resource/worker Base fixture. They
run the actual picker and OK/Cancel scripts with DOM construction doubled,
exercise 30-to-20 mineral confirmation/cancellation and queued duplicate input,
recheck unsupported designs and changed technology, reject another human's Base,
and complete both selected Former and Colony through actual upkeep and home
assignment. They do not claim graphical rendering or original chooser fidelity.
Changed C++ production/test files pass standalone syntax checking, and the cached
GSE executable loads the real picker fixture successfully. Runtime execution of
the new native groups is pending the combined integration build; no platform
suite was run.
