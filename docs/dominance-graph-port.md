# Functional lower-console Faction Dominance graph

The visible I page now requests an authenticated, owning-thread score-only
rebuild. This native builder operation updates the current history row and the
working scores; ordinary summary/text reads stay pure, and retained ranks stay
unchanged. Hidden I pages do not refresh scores. Repeated invalidations coalesce
behind one pending request; stale responses cannot replace the newest frame.
Requests behind a changed turn or unfinished upkeep do not mutate partial state.

Fresh worlds retain all seven canonical native source keys, independently of the
accepted/current participant roster. The frozen startup parser explicitly admits
the original default FACTIONS order. A University participant densely numbered1
therefore writes/plots native history slot3, with Gaia in source slot1. Inactive
current scores become zero; their past samples and all absent-series identities
remain retained. Native-slot samples are not indexed by transport order or labels.

Simulation format32 persists those identities with the whole history block.
Format31 history remains its original dense port-owner payload with native
identity absent; its16000 bytes, including unknown/future columns, are preserved.
The graph does not reinterpret or reconstruct that legacy payload. Older absent
history also stays absent. Unsupported turn1000+ and unmeasured display widths
remain explicitly unavailable; original readers beyond capacity are unclosed.

The graph consumes the measured1024×768 right-column clip and exact current-score
scale, turn sampling, signed truncation and native endpoint requests. It neither
stretches short histories nor adds axes, year ticks or nonempty legends. The
indexed line kernel preserves strict-positive midpoint ties and clipped-prefix
phase, uses inclusive endpoints, and draws nothing for a same-point request.
Its prefix jump bounds work by the visible major span, including tall old peaks.
The RGBA Surface uses opaque indexed colors and leaves the original console
backing visible elsewhere.

Normal/alternate slot colors come from actual PALETTE.PCX metadata rows23/31,
not executable pre-initialization constants or faction PCX body tints. Only the
retained exact SPARTANS key selects its alternate slot color. Display RGB uses
the established Gamma100 common cap and measured reserved colors; model palette
and quantization inputs remain unchanged.

Authorities: [history/geometry](behavior/dominance-graph.md),
[source-slot colors](behavior/dominance-graph-colors.md), and
[indexed line stores](behavior/indexed-line.md). The faction heading retains
the existing regular Arial12 presentation. Historical Windows font raster,
arbitrary custom/native-import source slots, other widths, native UI timer
scheduling and whole-screen original-game parity are not claimed.

A valid port roster may contain multiple owners using the same faction profile.
That roster has no unique native-column projection: graph requests are
unavailable and the native history block stays intact, while ordinary ranking
and turn upkeep continue. Scores are never merged into a guessed source slot.
Legacy format31 dense history keeps its prior writer and raw bytes.
