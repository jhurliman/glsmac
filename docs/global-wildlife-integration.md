# Global wildlife policy integration

`map/SmacGlobalWildlife` implements the reachable fauna decisions after the
forest/kelp pass in stock `537790`. It owns the incoming RNG copy and preserves
constructor-owned draws before subsequent samples. Sea search consumes its
1000th coordinate pair without testing it. The fungal shortcut deliberately
bypasses the fallback occupancy, region-area and water checks. Broods use the
actual newborn carrier's capacity, passenger sentry operations and stack
promotion; land births and unseen ambushes retain the native ordered search.

Every helper must operate on one detached transaction. Earlier constructor
occupancy and sight effects must be visible to subsequent queries. A failure
requires discarding the whole transaction; this policy does not provide rollback
for an arbitrary hook. Publication and script notifications belong after commit.

This is not activated in the live round controller. The shared birth publisher
now stages mixed Scout/Isle stacks with complete retained links, or binds an
unambiguous legacy singleton. Ambiguous legacy stack order and occupied Base
placement remain guarded. Global maintenance and wildlife upkeep/command phases
also remain separate integration work.

Validation currently covers four asset-free native test groups: no-effect gates,
capacity/order/Locust sequence and entry-only count gating, exact exhausted search
query budget and factory RNG, and no-Base ambush/empty-land/omniscience guards.
The test factory models only the state needed by these structural controls; it
is not proof of original constructor effects or live gameplay. Production-file
analysis and focused two-file ASan/UBSan pass (other linked objects normal,
leak detection disabled). The opt-in `GLSMAC_GLOBAL_WILDLIFE_REFERENCE` test compares all 30 frozen
original policy returns: exact ordered constructor/sentry/head requests, sea/land

## Prepared Map flora publication

`Map::PrepareGlobalSpread` stages physical fungus/forest/kelp changes, existing
full observer memories, the packed retained source and an optional batch render
payload. Discard and preparation failure leave every live authority unchanged.
Commit rejects changed policy, knowledge, consumed terrain or affected physical
appearance before any publication, then moves the policy/knowledge and writes
the physical fields. Compile-time checks require those final owning assignments
to be nonthrowing. A prepared transaction belongs to one Map and cannot commit
twice. The caller retains the round/RNG/faction-status ticket, stays synchronous
without scripts/yields, and queues render notifications after commit.

`WithLiveGlobalSpread` permits only projected rain, rockiness, exploration and
mapped current/remembered material bits. Every other retained bit must match;
the existing strict ordered journal then validates the final plane. Visibility
and current improvements use the existing retained-world V2 policy codec, with
no new wire format. This remains a flora source, not complete current occupancy,
region, territory or native AI authority.

Unexplored native improvement words are not necessarily zero. A flora write can
change their partial history without establishing a complete higher-level port
memory. Preserve that packed result, update existing full memory records, and
leave unavailable records unavailable. The integration control proves both the
unknown-target case and a known-target case whose remembered Road survives

## Reversible flora query view

`Map::QueryGlobalSpread` validates the prepared Map inputs, exposes detached
copies of its candidate policy/knowledge and the staged physical growth to a
synchronous C++ consumer, then restores the original values. A consumer can
prepare another detached subsystem while seeing flora effects. It must not run
scripts, yield, publish live state, or retain borrowed view references. Owned
results may escape. This is not rollback for arbitrary consumer mutations.

The restore guard is allocated before any ownership change. Policy/knowledge
swaps are compile-time nonthrowing; normal and exceptional exits restore affected
physical fields, readiness, and the original native geometry/cache ownership.
A Map-wide query guard rejects recursive flora prepare/query/commit, including
publication through a different prepared object. Queries and commits share the
same stale-input validation. Render atlas updates and notifications are untouched.

The integration test observes actual staged physical/packed/known-memory fields,
warms candidate height geometry, injects a consumer exception, then verifies the
original values and cache identities. It also checks a successful query, known
versus unavailable memory, cross-object publication rejection, and later commit.
Seven affected groups pass normally and under three-TU focused ASan/UBSan (Map
producer, native geometry consumer and fixture; other objects normal, leak
detection disabled), including the optional nine original checkpoints with the
receipt supplied. Both production consumers pass targeted analysis. Combined
native-birth/global-policy execution and the round controller remain work; this
query view does not claim those effects have run in GLSMAC.
