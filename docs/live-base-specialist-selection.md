# Live Base specialist selection

Clicking a displayed citizen in the owned Base inspector opens an optional native-issued selection request. Choices use the frozen installed specialist catalog, current technology, obsolescence/current-type exception and population/psych eligibility. Worker and admitted specialist choices go through authenticated local commands, including the existing stamped Colony Screen continuation. The port does not add an alternate allocation calculator.

Opening performs the measured preliminary resource/worker recalculation; Cancel and same-type choice retain that completed prelude. An accepted different choice clears only citizen management, applies the original stored-slot mutation, then recalculates and publishes allocation, stable Pop identities, worked-tile links and current resource/support cache together. Recalculation normalizes food but never posts food, minerals, faction income or research. Choosing Worker decrements the count without shifting the clicked stored type: final worker allocation determines whether the freed slot can be worked.

Requests contain a native-issued ephemeral identity and post-prelude turn/Base snapshot. They never decode caller snapshots into gameplay. Foreign owners, malformed/ineligible choices and unadmitted overflow reject before publication; duplicate, cancelled and stale answers cannot replay a mutation. The optional view closes on Base changes, close/despawn, turn transition and mandatory questions. Saving does not persist an open optional menu; the actual saved allocation/settings remain authoritative.

The original rules are documented in [manual specialist selection](behavior/manual-specialist-selection.md). The exposed UI covers an actual clicked Pop/worker context. Background/highest-index creation, more than sixteen live stored specialists, full citizen/Psych/riot consequences, original menu artwork/layout and reference-game input/network-lock fidelity remain open. The current native allocation projection admits at most sixteen stored specialists, so worker creation at that boundary offers only Worker and explains the limit.
