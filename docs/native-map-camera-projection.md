# Ordinary map camera projection

The original [ordinary terrain geometry](behavior/ordinary-terrain-projection.md) uses 96x48 zoom0 diamonds with integer pixel-height displacement. #320 retained those heights and #322 connected object callers, but the port still projected a world-space square through a uniform-scale 45-degree view. Its flat diamonds had height/width approximately sqrt(1/2), and the native H/48 height normalization was correspondingly too large relative to tile width.

For maps carrying retained original Planet provenance, the frontend now scales camera Y and Z by sqrt(1/2) relative to X. The existing camera rotation then produces equal/opposite half-scale Y/Z coefficients: a one-world-unit diamond is96x48 at zoom0 calibration, and each H/48 world-height unit rises exactly H pixels. This keeps display/picking on the same camera and retains the existing world topology and stored geometry. Tile recentering, camera baseline, fit/range and legacy minimap selection use the matching coefficient. The backend copies that provenance into the map-data response; all-ocean maps retain native projection even though no tile carries a land-height anchor. Maps without original provenance retain their former camera constants.

An actual scene::Camera matrix test projects all five vertices of18 original height contexts into literal flat-diamond coordinates centered at(576,288), minus the original native per-vertex heights. This proves the geometric projection and calibrated height scale; the translation is a controlled test calibration, not a claim that the original game's camera navigation, zoom selection or viewport origin is reproduced.

Artwork follow-up: the existing atlas/model/overlay renderers still have their earlier port world-space dimensions and pivots. Those must be replaced with the separately measured loaded sprite rectangle and object surface contracts under this projection. Font bitmaps remain pixel-sized. Terrain texture sampling, lighting/CLUT raster, landmark deformation and water geometry remain open. No whole-frame screenshot parity is claimed.
