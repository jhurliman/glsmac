# Terrain-aware map objects and improvements

The original [ordinary map object callers](behavior/ordinary-map-object-anchors.md) distinguish the terrain fan center from the floored mean of the four outer heights. This matters on isolated hills and coasts: the model, population/order/health overlays and improvements must move together with their original projector height, rather than the hill center or an unfloored floating-point average.

Backend MapObject coordinates, movement endpoints and frontend Tile object coordinates now use the retained projector anchor introduced in #321. Existing local artwork and badge offsets remain separate. Initial terrain sprites and the ordinary/appearance update callers also use that projector height when native land metadata is present. Legacy geometry preserves its existing center or floating outer mean, respectively; water remains on its existing path. Display and picking retain the terrain fan, not the object anchor.

The source contract includes four absolute zoom0 Base/name/Scout fixtures, 48 coordinate assertions, four model surface setups and 20 bunker/airbase/mine/solar/condenser calls. The port tests exercise the actual finalizer-to-frontend/backend object callers and initial/staged improvement callers, including a fractional outer mean that distinguishes native flooring from legacy behavior. They do not establish absolute camera, model ink, loaded sprite rectangle, palette/raster, water or landmark parity. Loaded artwork destination rectangles have since been measured separately in the reference workspace; applying those local artwork offsets is the next implementation follow-up.

Validation: cached incremental build; six focused native terrain/projector/update groups with allocation tracking; targeted correctness analysis of the five changed production translation units (three object callers and two improvement callers). No ownership or transport implementation changed in this follow-up. Visual runtime evidence is recorded in the PR description.
