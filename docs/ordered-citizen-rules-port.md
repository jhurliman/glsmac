# Ordered citizen arithmetic

The native SmacCitizens module supplies the measured ordinary/faction and
assimilation prefix, global-list bureaucracy distribution, facility/project
inputs, initial/Psych/facility conversion, police/pacifism, late projects and
suppression, and Golden Age/riot admission. Calming burden is retained separately;
it is not a third disjoint population group or an assumed icon type.

This module accepts resolved owned inputs. It does not construct live garrison,
territory, project ownership, citizen views, status writes or riot consequences.
Those callers remain a separate integration slice; a pure rule passing tests is
not a playable Psych page or a completed citizen system. Negative custom faction
parameters have their checked prefix arithmetic, but negative conversion inputs
remain explicitly outside the measured early conversion domain.

The later citizen-upkeep-composition receipt corrects the earlier static status
ordering: incoming riots gate production, growth uses incoming Golden Age, the
second resource/citizen pass precedes status, and new status never retroactively
reposts earlier food or minerals. Integration must stage that sequence atomically.

Validation: 178 literal named original cases across seven native groups, plus a
bounded extreme-talent/negative-police input group. All eight groups pass normally
and with the production rule/test TUs instrumented by ASan/UBSan (remaining linked
objects reuse the coherent cached build; leak detection disabled). Targeted C++
correctness analysis of SmacCitizens.cpp reports zero failures. No full platform
matrix or installed-asset renderer was repeated for this pure arithmetic slice.
